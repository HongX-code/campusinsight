只做内环，材料里就只剩「用过了」；两环同步，才能回答「这段改动是哪句提示词带来的、当时怎么验证的」。

三层证据（缺任何一层都容易被判为「只上传过代码」）

L1
可复现

命令与退出码：doctor / index / verify / ci_gate.py、双集评测与真实集审计。

L2
可追溯

提示词与产出一一对应：codearts/prompts/ 独立文件、会话对照表、开发日志的「提示词编号」列。

L3
可核验

材料与代码自洽、时间真实：交付件页数 / 字数 / 口径体检、带日期的过程截图、逐日检查清单。

判定原则：没有命令输出的结论标「待验证」，没有截图的状态不写「已完成」。

python scripts/codearts_tools.py doctor

python scripts/codearts_tools.py bootstrap --check

python scripts/codearts_tools.py all

# 1 每天收工：9 阶段门禁（含环境体检，失败即停）
python scripts/ci_gate.py

# 2 改了主文档的提示词 / 排期后
python scripts/codearts_tools.py split
python scripts/codearts_tools.py split --check
python scripts/codearts_tools.py verify

# 3 改了文档口径后重建交付件（相对工程根 ../../）
python ../../申报材料/build_ppt.py
python ../../申报材料/fill_form.py
python ../../申报材料/export_pdf.py
python ../../申报材料/export_pdf.py --check

# 4 每次改动后：现场采集证据 + 口径自动回灌（进阶文档 A8）
python scripts/evidence.py --collect
python scripts/evidence.py --check
python scripts/scale_sync.py --check
python scripts/mutation_audit.py

本机 python 指向未装依赖的 3.13，正确前缀是 py -3.12（或激活 venv 后直接用 python）。 详见主文档 §1.0；doctor 会现场给出你机器上的可用前缀，并顺带检查 node、可选依赖与 Office 文件占用。
