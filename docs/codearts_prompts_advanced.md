## 0. 这份文档解决什么问题

不是「再写一批提示词」，而是补上三个在真实使用中会静默出错的缺口。

### 0.1 常驻上下文会漂移，而且没人检查它

`.codeartsdoer/AGENTS.md` 是 CodeArts 每次会话自动加载的工程事实，但它一直停留在
11 月 7 日的基线：写着旧的源码行数、旧的自检项数、旧文档份数，也不知道后来新增的
启动体检、变异测试、证据链。更关键的是——**它不在任何口径校验的扫描范围内**，
所以旧值可以一直安静地待下去，智能体每次开工都拿到一份过期地图。

**处置**：本轮已把 AGENTS.md 改成「指向 `docs/metrics.json` 现场快照」而非写死数字，
补进近三轮的工程能力与 4 条新硬约束，并纳入 `verify` 的锚点检查与旧值行级扫描。
下次再漂移会当场变红，而不是等答辩时被问出来。

### 0.2 提示词停在「方案层」，缺少可执行契约

v1.x 的 P1—P10 写清了「要做什么」，但没有统一约束「允许改哪些文件、验收命令是什么、
失败怎么回滚、证据写到哪里」。结果就是每个会话都要重新对齐一遍，智能体容易顺手重构、
把待验证写成已完成、或者只改一处数字造成口径分裂。

**处置**：本文提出**契约式提示词（Contract-First Prompting）**，三层契约固定下来：

| 层 | 契约 | 回答的问题 |
| --- | --- | --- |
| 上下文契约 | §2 B0 | 智能体接手时，哪些事实是权威的、哪些数字不能凭记忆写 |
| 执行契约 | §3 A0 | 一次改动允许碰什么、输出什么格式、失败怎么退回去 |
| 验收契约 | §5 验收矩阵 | 哪条命令、什么输出、退出码多少才算「已验证」 |

### 0.3 近三轮新增的工程能力，没有进入 CodeArts 的任务清单

启动链路加固、检查工具静默缺陷审计、11 组变异测试、现场证据链与口径自动回灌，
这些能力已经落盘，但 v1.x 的任务提示词里没有对应项。智能体接手时不知道它们的存在，
很可能「好心」把行级豁免改回整文件白名单、把弱断言再加回来、或者手工改 README 数字。

**处置**：A8 / A9 把「证据链维护」「检查工具可信度」写成常设任务；A1—A7、A10 覆盖
云端、留痕、部署、压测、视频、人工实验、开源、提交前收口这些**真正还没做完**的事。
每条都带真实命令与期望输出，做完能归档、没做完能如实标注。

### 0.4 本文刻意不做的事

- 不新增第 12 份独立提示词文件：A 系列不参与 `split`，避免牵动 11 份口径与 PPT / DOCX 重建。
- 不把「方案 / 模板 / 工具」包装成「已完成」：所有未验证项在 §7 单列，A 系列提示词只描述动作。
- 不在正文写死规模、项数、文档份数：一律引用 `docs/metrics.json`，防止再制造一份会漂移的副本。
- 不引入新依赖、不改架构、不改设计变量：这些硬约束由 B0 与 A0 原样带上。

## 1. 投喂方式与开工前检查

### 1.1 三种投喂方式

| 方式 | 适用 | 做法 |
| --- | --- | --- |
| **整份常驻** | 换人接手、开新会话、长时间协作 | 把 §2 B0 整段粘进会话开头；`.codeartsdoer/AGENTS.md` 客户端会自动加载，两者内容一致、互为备份 |
| **单条复制** | 推进一项具体待办 | 复制 §4 对应 A 编号的 ```text``` 代码块整段；末尾追加 §3.1 的 A0 契约段（或说「遵守 A0」） |
| **短追问** | 上下文快满、移动端、纠偏 | 用 §3.5 的回滚话术或 §6 陷阱表里的「正确做法」一句追发，不重发整份 |

**一条会话只做一条 A 任务**。多个任务混在一个会话里，最容易发生「顺手重构」和「证据串台」；
做完一条、跑完验收、写完留痕，再开下一条。

### 1.2 开工前 5 条命令（每条 A 任务之前都跑）

```bash
# 1 环境与解释器前缀（任何解释器都能跑，脚本只用标准库）
python scripts/codearts_tools.py doctor

# 2 代码库索引覆盖（缺文件先在客户端全量重建索引，不要凭猜测回答）
python scripts/codearts_tools.py index

# 3 口径核对：确认磁盘现状与上次采集的快照一致，纯只读
python scripts/evidence.py --check

# 4 本地访问链路体检（版本 / 依赖 / 端口 / 数据库 / 页面资源）
python run.py --check

# 5 提交目录骨架完整性（幂等，不覆盖已填内容）
python scripts/codearts_tools.py bootstrap --check
```

若第 3 条报「口径不一致」，说明有人改了代码或文档却没跑采集——**先跑
`python scripts/evidence.py --collect`**，不要手工改数字去凑。
若第 4 条报端口被占用，按它给出的动态端口提示处理；不要改框架、不要删数据库。

### 1.3 本地访问地址（最容易踩的一条）

默认监听 `127.0.0.1`，浏览器地址是 **`http://127.0.0.1:8000/`**。
`0.0.0.0` 是「监听所有网卡」的通配地址，**不是网址**，只有云端部署才显式设
`APP_HOST=0.0.0.0`。启动用 `python run.py --open` 或双击 `start_server.bat`。

## 3. A0　通用执行契约（每条 A 任务都附加）

### 3.1 提示词正文（可直接复制，或让智能体「遵守 A0」）

```text
【执行契约 A0 —— 本次改动全程有效】

一、动手前
1. 先跑开工 5 条命令（doctor / index / evidence.py --check / run.py --check / bootstrap --check），
   把结果贴给我；任何一条非 0 先停下说明原因，不要带着红项继续改。
2. 先输出四件事并等我确认：问题分析、拟改动文件清单（精确到路径）、影响面、
   验证方式。不要一次性重写整个文件，不要顺手重构无关模块。
3. 只读相关调用链上的全部文件后再下结论；引用工作区外文件前先确认它真实存在。

二、改动中
4. 最小 diff：标明文件路径与函数 / 行号，不新增依赖、不改架构、不改设计变量。
5. 允许改动的文件以本条任务的白名单为准；黑名单里的文件一律不动，
   需要动时先单独说明理由并等我确认。
6. 涉及口径数字时，不改数字本身，改完统一跑 python scripts/evidence.py --collect 自动回灌。
7. 涉及 tests/、校验逻辑或检查脚本时，新增断言必须能在对应缺陷注入下失败；
   完成后跑 python scripts/mutation_audit.py。
8. 不放宽输入校验来消掉报错：非法输入必须显式返回 400 并说明原因。
9. 容错只针对无法解析的值，合法记录一条都不能少；补一条断言证明正常数据仍被返回。

三、交付时
10. 输出五段式：① 改了什么（文件 + 行号）② 为什么这样改 ③ 验收命令与实际输出
    ④ 口径与交付件影响（列出需要同步的 docs / PPT / 表单文件及重建命令）
    ⑤ 状态结论（逐项标注「已验证 / 待人工 / 待资源验证」，并给出证据来源）。
11. 「已验证」必须有本次实际执行过的命令与输出；没有输出就写「待验证」，
    不要写「应该没问题」。
12. 末尾给出本节任务要求的验收命令；按 doctor 输出替换解释器前缀。
```

### 3.2 五段式输出契约

| 段 | 必含内容 | 常见缺失 |
| --- | --- | --- |
| ① 改了什么 | 文件路径 + 函数 / 行号 + 最小 diff | 只说「优化了逻辑」 |
| ② 为什么 | 根因、调用链、为什么旧实现会出问题 | 直接给结论没有依据 |
| ③ 验收 | 实际命令 + 实际输出 + 退出码 | 写「已验证」但不贴输出 |
| ④ 影响面 | 需同步的 docs / PPT / 表单 / 截图 + 重建命令 | 改了新文件却没说要同步材料 |
| ⑤ 状态 | 逐项「已验证 / 待人工 / 待资源验证」+ 证据来源 | 把待办写成已完成 |

### 3.3 允许改动 / 禁止改动清单（默认，具体任务可覆写白名单）

| 类别 | 路径 |
| --- | --- |
| ✅ 通常允许 | `app/`、`tests/`、`scripts/`（按任务）、`docs/`（按任务）、`config/sources.json` |
| ⚠️ 需显式确认 | `申报材料/*.py`（会牵动 PPTX / PDF / DOCX 重建）、`.codeartsdoer/AGENTS.md`、作战台 HTML |
| ❌ 默认禁止 | `docs/benchmark.md`（由脚本生成）、`codearts/prompts/*`（由 `split` 生成）、`data/*_标注集*`、`requirements.txt`、`.env`、`*.db`、`file-index.db`、`11_CodeArts使用记录/` 里**已填写**的真实记录 |

### 3.4 每次改完的验收基线

```bash
python tests/test_smoke.py                       # 退出码 0；通过 N 项、失败 0 项
python scripts/mutation_audit.py                 # 退出码 0；全部变异被检出

```

仅在改动范围涉及对应资产时才额外跑：`split --check`（提示词）、`bootstrap --check`（骨架）、
`build_ppt.py` / `fill_form.py` / `export_pdf.py`（交付件）、`capture.py`（截图）。
**不要为了「看起来全面」把无关重建命令全跑一遍**——Office 文件被预览占用时反而会引入噪声。

### 3.5 失败回滚与追加话术

| 观察到的偏差 | 在同一会话里直接追发 |
| --- | --- |
| 一次性重写整个文件、顺手重构 | 「回退无关改动，只保留 X 文件第 N 行附近的最小 diff，其余文件恢复原状。」 |
| 编造云资源运行结果 | 「当前没有凭证，云相关结论改为『代码就绪，待开通验证』，并列出团队实际要执行的动作。」 |
| 动了评测数据或性能表述 | 「不要改 tests/ 与 docs/benchmark.md；性能口径只由 scripts/sync_metrics.py 回灌。」 |
| 手工改了 README 里的数字 | 「撤销这处手工替换，改跑 python scripts/evidence.py --collect 让全部交付件一起对齐。」 |
| 把「跳过脏数据」实现成丢正常数据 | 「容错只针对无法解析的值；补一条断言证明合法记录仍被返回。」 |
| 悄悄放宽输入校验 | 「不允许把 400 改成静默纠错，非法输入必须显式报错并说明原因。」 |
| 新增断言在缺陷注入下仍全绿 | 「这条断言是恒真的；补一条能被对应变异触发的负向用例，再跑 mutation_audit.py。」 |
| 把待办写成已完成 | 「逐项标注证据来源；没有截图或命令输出的一律标『待验证』。」 |
| 回答里出现「应该没问题 / 已验证」却没跑命令 | 「把『已验证』改成『待验证』，或贴出你实际执行过的命令与输出。」 |
| 引用了工作区外文件 | 「先确认文件真实存在再引用；路径以工程根为基准，不存在的写『需团队复制进工作区』。」 |

- **黑名单**：真实凭证、`11_CodeArts使用记录/` 已填内容、`docs/质量证据总览.html` 的边界清单
- **验收与期望**：终检 6 条命令退出码全 0；占位清单逐条有责任人；状态词只有「已就绪 / 待补齐 / 待验证」
- **失败处理**：任一项未通过 → 单列并给出补齐动作，不带病打包
- **留痕**：终检报告、会话导出、采纳说明

## 6. 已知陷阱清单（真实踩过的，不要重犯）

| # | 陷阱 | 后果 | 正确做法 |
| --- | --- | --- | --- |
| 1 | 把 `0.0.0.0` 当浏览器地址 | 浏览器报「无法访问此页面」，且服务其实没起 | 本地用 `127.0.0.1`；云端才显式设通配监听；先跑 `run.py --check` |
| 2 | 旧值扫描用整文件白名单 | 往白名单文件里新增禁用旧值仍全绿 | 行级豁免，仅含明确说明性标记的行放过 |
| 3 | 回灌用 `count=1` | 同一锚点出现第二处时旧值原样残留 | 全量替换；同锚点 >1 处时打印处数 |
| 4 | `split --check` 只比对已知文件 | 目录里多一个 `P99_bogus.md` 仍 PASS | 同时检出 `FILE_MAP` 之外的 `P*.md` |
| 5 | 端点数只打印不核对 | 文档写错端点数仍判 PASS | 从现场值硬核对，写错即 FAIL |
| 6 | 端口占用时只看 health 返回 200 | 别的服务冒充本服务 | 校验 `app` 身份标识 + `status` |
| 7 | 弱断言 `len(a) <= 1 and len(b) >= len(a)` | 语料只有一条命中时恒真 | 准备多条命中的探针语料，单元层 + 接口层双探针 |
| 8 | 去重用例只重发完全相同 payload | 正文不参与指纹也测不出来 | 补「同标题不同正文不算重复」 |
| 9 | 负向哨兵打印 `[FAIL]` | 报告里所有缺陷的「触发项」都变成哨兵，读起来像哨兵自己失败 | 哨兵静默（`quiet=True`），计数完整回滚 |
| 10 | 断言名唯一性守卫放在 `main()` 开头 | 那时列表还是空的，守卫恒真 | 放在收尾处判断 |
| 11 | 检查脚本注释里写历史数字 | 被旧值扫描正确抓到，采集当场变红 | 注释里不写易变数字，或加说明性引用标记 |
| 12 | PPT 表格三行都写「约 3100 行 Python」 | 手工估算相加远超实际，无法核验 | 改成可核验的定性指标（端点数 / 规则数 / 截图数 / 变异检出） |
| 13 | 手工改一处 README 数字 | 其余八处没跟上，口径分裂 | 一律跑 `evidence.py --collect` 自动回灌 |
| 14 | 通过命令行管道写含反斜杠的 Python 正则 | 反斜杠被转正斜杠，正则静默损坏 | 用专用文件写入，写完立刻 `py_compile` |
| 15 | 把模板 / 空骨架 / 作战台截图贴进答辩材料 | 等同于自证「尚未使用」 | 真实会话导出 + 带日期截图 + 已填写记录 |

## 9. 维护规则与版本演进

1. **新增 / 改写 A 系列提示词** → 只改本文；不跑 `split`；跑 `verify` 确认本文存在且关键锚点齐全。
2. **新增 / 改写 P 系列提示词** → 改 v1.x 主文档 §2 / §3 → 跑 `split` → 跑 `split --check`；保持 11 份。
3. **任何代码 / 文档改动** → 跑 `evidence.py --collect`，让规模与项数口径自动回灌；不手工改数字。
4. **新增 `docs/*.md`** → 文档份数会由 `scale_sync.py` 自动回灌到架构 / 符合度矩阵 / PPT / 表单；
   确认三件交付件重建后页数与字数仍在限内。
5. **改动 `AGENTS.md`** → 保持「指向 `metrics.json`」而非写死数字；
   `verify` 会检查它的关键锚点，并把它纳入旧值行级扫描。
6. **改动作战台 HTML** → 内容以 v1.x 主文档与本文件为准，不另立口径；改完核对两档视口无横向溢出。
7. **新增检查工具或断言** → 跑 `mutation_audit.py`；涉及检查侧逻辑时按 A9 做反向探针。
8. **状态变化** → 只有拿到真实证据（截图 / 命令输出 / 会话导出）才从「待补齐 / 待验证」改为「已验证」，
   并同步本文 §7、`docs/质量证据总览.html` 边界清单、符合度矩阵、PPT 与申报表。
9. **版本演进** → 本文只记录「下一阶段实操」层；体系说明与逐日排期仍归 v1.x 主文档，
   两者不合并、不互相复制正文，避免再次出现「两份会漂移的副本」。
10. **每次收工** → 按 §3.6 格式写留痕；跑 §5 验收矩阵中与本次改动相关的命令；
    把「未验证」项原样留到第二天，不为了收工好看而勾掉。
