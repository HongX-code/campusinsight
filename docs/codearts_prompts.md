### 方法论框架：双闭环 · 三层证据

赛题考察的是「想法到应用」的**过程**，因此本体系同时驱动两条闭环，而不是只交一份生成结果。

| 闭环 | 链路 | 本文件对应 |
| --- | --- | --- |
| 内环 · 开发闭环 | 需求理解 → 生成／修改 → 构建 → 调试定位 → 修复 → 测试 → 集成 → 部署 | P1 / P5·P8 / P5 / P2 / P2 / P3 / P6 / P7，§4.1 |
| 外环 · 证据闭环 | 提示词 → 会话导出 → 过程截图 → 采纳／排错说明 → 回归输出 → 归档 | §5.2 七类截图、§5.3—§5.6 模板、`11_CodeArts使用记录/` |

两条闭环之间用**三层证据**咬合，缺任何一层都容易被评为「只上传过代码」：

| 层级 | 回答的问题 | 具体载体 |
| --- | --- | --- |
| L1 可复现 | 结论能不能原样跑出来？ | `codearts_tools.py doctor / index / verify`、`ci_gate.py`、双集评测与真实集审计的命令及退出码 |
| L2 可追溯 | 这段代码是哪句提示词带来的？ | `codearts/prompts/` 独立文件、会话对照表、开发日志的「提示词编号」列 |
| L3 可核验 | 材料与代码是否自洽、时间是否真实？ | 交付件页数／字数／口径体检、带日期的过程截图、逐日检查清单 |

> 三层证据的判定原则：**没有命令输出的结论标「待验证」，没有截图的状态不写「已完成」**。
> 这也是 §6 红线与 §9.3 状态边界的由来。

## 0. 先分清两类提示词，不要混用

本项目里存在两种完全不同的 Prompt，写材料、做答辩时务必区分：

| | A 类：运行时解析提示词 | B 类：开发期工具提示词 |
| --- | --- | --- |
| 发给谁 | 华为云 MaaS 大模型（用户点击「解析」时调用） | 华为云码道 CodeArts 代码智能体（开发过程中调用） |
| 作用 | 把通知原文解析成结构化字段；问答时约束只依据原文片段作答 | 需求理解、代码生成、缺陷定位、测试生成、构建部署、文档同步 |
| 代码位置 | `app/services/analyzer.py` 的 `SYSTEM_PROMPT`、`app/services/qa.py` 的 `QA_SYSTEM` | 本文件 §2 / §3，以及 `.codeartsdoer/AGENTS.md` |
| 材料表述 | 「AI 理解通知内容」 | 「CodeArts 参与开发全过程」 |

**本文档只负责 B 类。** 赛题要求体现的是「华为云产品在需求理解、代码生成、项目构建、问题修复、部署上线等环节的使用价值」，即 B 类提示词驱动的完整链路，而不是把运行时解析 Prompt 当成开发留痕交上去。

## 1. 投喂前准备（务必先做，约 5 分钟）

### 1.0 运行环境与命令基准（v1.1 新增，最先跑这一条）

**先把解释器这件事说清楚，否则后面所有验收命令都会以同一种方式失败。**

本工程在 **Python 3.12** 下开发与验证，依赖清单为 `requirements.txt`。文档里出现的
`python` 是**命令代称**，不是「随便哪个 python 都能跑」：本机 `python` 指向 3.13，
未安装 fastapi / SQLAlchemy / httpx 等依赖，直接照抄会得到 `ModuleNotFoundError`；
而 `py -3.12`（或 `/d/Python/Python312/python`）依赖齐全。

一键体检，输出可直接复制的解释器前缀、node 状态与交付件占用情况：

```bash
python scripts/codearts_tools.py doctor          # 任何解释器都能跑，脚本只用标准库
python scripts/codearts_tools.py doctor --strict # 供门禁调用：当前环境不可用时返回非 0
```

doctor 会依次探测 `py -3.12` / `py -3` / `python3.12` / `python3` / 工程内 venv 与常见
Windows 安装路径，找到依赖齐全的解释器后输出推荐前缀。按它替换文档命令即可：

| 环境 | 推荐写法 | 示例 |
| --- | --- | --- |
| 本机 Windows（Git Bash / PowerShell / CMD） | `py -3.12` | `py -3.12 scripts/ci_gate.py` |
| 已激活 venv，或 `python` 就是 3.12 | `python` | `python scripts/codearts_tools.py all` |
| Linux / 构建机 | `python3.12` 或激活 venv 后的 `python` | `python3.12 scripts/ci_gate.py` |
| 换机后首次使用 | 先装依赖 | `py -3.12 -m pip install -r requirements.txt` |

三条约束：

- `ci_gate.py` 的第 1 阶段就是 `doctor --strict`。**用错解释器时门禁会在第 1 阶段停下并打印正确前缀**，
  不会让后面 8 个阶段用错环境、抛一串看不懂的导入错误。
- 申报脚本另需 `python-pptx` / `pypdf` / `python-docx`；`export_pdf.py` 还需 Windows 上的
  `pywin32` 与本机 PowerPoint。doctor 会把它们列为「可选依赖」，缺失时 `verify` 中相关检查记 SKIP，
  不阻塞自检与评测。
- 若 PPTX / PDF / DOCX 正被 Office 预览占用，doctor 会列出被锁文件名；关闭预览再重建交付件，
  不要强杀编辑器或删锁文件。

> **不硬编码绝对路径**：文档与脚本都用可移植前缀，本机实测值仅作为示例写在此处。

```bash
# 5 性能口径（仅在改了性能相关表述或复跑基准后执行）
python scripts/benchmark.py
python scripts/sync_metrics.py

# 6 交付件（仅在改了文档口径后执行）
python ../../申报材料/build_ppt.py
python ../../申报材料/fill_form.py
python ../../申报材料/export_pdf.py

# 7 界面（仅在改了 CSS/JS/HTML 后执行）
python scripts/capture.py     # 重拍 24 张并逐张目检

# 8 提交前一键体检（口径、旧值、页数、字数、资产完整性）
python scripts/codearts_tools.py verify
python scripts/ci_gate.py     # 全流程门禁，任一步失败即中止
```

**口径扫描**已内置在第 8 步的 `verify` 子命令中，按**行**判定而不是整文件豁免：

的行可放过，其余任何命中都会让体检变红；白名单之外的文件出现旧值一律失败。
手工复查直接跑 `verify`，**不要用整文件 `--exclude` 的 grep**：
说明：实测这种写法会把新写进 `test_report.md` 的旧值一起漏掉。

```bash
python scripts/codearts_tools.py verify
```

### 9.2 单一数据源与幂等

- **提示词正文只在本文件 §2 / §3 维护**。`codearts/prompts/*.md` 由 `codearts_tools.py split`
  从本文件自动拆出，禁止手改拆分结果；改动 Prompt 后先跑 `split`（不带 `--check`）再跑 `split --check`。
- **进阶提示词正文只在 `docs/codearts_prompts_advanced.md` 维护**：B0 注入块、A0 执行契约与
  A1—A10 任务提示词不参与 `split`，`codearts/prompts/` 固定 11 份；该文档不写死易变数字，
  口径一律引用 `docs/metrics.json`，并由 `verify` 检查关键锚点。
- **性能数字只在 `docs/benchmark.md` 维护**，由 `scripts/sync_metrics.py` 回灌；本文件不复制具体数值之外的结论。
- **留痕模板正文只在 `codearts/templates/` 维护**，提交目录里的同名文件由 `bootstrap` 派生；
  骨架只在首次生成，重复运行一律保留已填内容，不会把真实记录洗回空白模板。
- **执行看板内容以本文件为准**：`codearts/CodeArts实操作战台.html` 是给人用的只读视图，
  其中的短提示词、逐日任务与七类截图清单均来自本文件 §4.2 / §4.4 / §5.2，不另立口径。
- `doctor` / `bootstrap` / `split` / `index` / `verify` 五个子命令均可反复运行，
  不改无关文件、不安装依赖、不生成伪证据；`doctor` 与 `--check` 模式更是纯只读。

### 9.4 维护规则

1. 新增或改写任一 Prompt → 跑 `split` 重新生成独立文件 → 跑 `split --check` 与 `verify`；
2. 新增 `docs/*.md` 或 `scripts/*.py` → 更新 README / 架构 / 符合度矩阵里的份数与行数口径，
   并重建 PPTX / PDF / DOCX；
3. 每次复跑 `benchmark.py` → 紧接着跑 `sync_metrics.py`，再跑 `verify`；
4. 改了 §4.2 排期 / §4.4 短卡片 / §5.2 七类截图 → 同步作战台 HTML 的对应数组，
   再跑 `split` 与 `verify`；作战台不另立口径。
5. 改了 `codearts/templates/` 下的模板 → 首次生成用 `bootstrap`，需要刷新骨架时跑
   `bootstrap --check` 确认差异，再决定是否 `--force`（**已有真实记录的目录不要 force**）。
6. 每次换机 / 换解释器 → 先跑 `doctor`，按输出的前缀执行 `ci_gate.py`。
7. 新增 / 改写 A 系列提示词 → 只改 `docs/codearts_prompts_advanced.md`，不跑 `split`；
   跑 `verify` 确认关键锚点齐全。改动 `.codeartsdoer/AGENTS.md` → 保持「指向 `metrics.json`」
   而非写死数字，`verify` 会检查锚点并把它纳入旧值行级扫描。
7. CodeArts 实操留痕完成后 → 只改状态与附件清单，**不改写本文件里的提示词正文**，
   保证「当时的 Prompt」与「当时的产出」可一一对照。
