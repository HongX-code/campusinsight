# 数据集说明

初赛评审明确要求说明"数据集的选取与数据处理"，本文档记录数据的来源、规模、标注口径与清洗流程。

## 1. 数据来源

数据集由**两部分**构成，两者的作用不同，评测时严格区分：

| 部分 | 规模 | 来源 | 用途 |
| --- | --- | --- | --- |
| A. 真实采集集 | 42 份 | 由本项目采集引擎从武汉理工大学 7 个公开栏目实时抓取 | 证明系统面对真实网页时可用；提供可回溯的真实 URL |
| B. 构造评测集 | 32 份（开发 24 + 留出 8） | 队员按真实通知体裁仿写，人工标注 | 用于规则迭代与指标评测——真实通知的字段标注成本高，且部分通知本身不含截止日期，无法用于评测 |

真实采集集**不做人工标注**，用于"端到端可用性"验证（能否抓到、正文是否干净、字段是否抽得出）；
构造评测集**逐字段人工标注**，用于精确率/召回率计算。两类数据都不含真实姓名与联系方式。

### 1.2 构造评测集的选取原则

| 原则 | 说明 |
| --- | --- |
| 体裁覆盖 | 学科竞赛、奖助学金、学术讲座、科研项目、志愿服务、社会实践、校园活动、实习就业 8 类 |
| 排版覆盖 | "一、二、三"章节式、`【标签】`内联式、`标签：内容`内联式、纯段落式 |
| 时间表述覆盖 | 绝对日期、区间（`11月3日至11月20日`）、相对时间（`本月底前`）、多截止日并存 |
| 条件表述覆盖 | 年级门槛、成绩排名、经济状况、团队人数、品行纪律、优先项 |
| 规模控制 | 开发调试 24 份，留出检验 8 份，合计 32 份。刻意不追求大数据量——一周周期内，标注质量比数量更重要 |

## 3. 标注口径

标注由非开发者成员完成，目的是避免"自己写规则、自己验证"造成的评估偏差。争议较大的样本由两人复核。

### 3.1 字段定义

| 字段 | 定义 | 边界处理 |
| --- | --- | --- |
| `category` | 通知的业务类别，取值见 8 类 + 其他 | 以"学生要做什么"判定，不以发文单位判定 |
| `deadline` | 学生需要完成某动作的最后日期（报名/提交/申报） | 通知未给绝对日期则标 `null`；举办时间、公示时间、评审时间**不算** |
| `target` | 适用对象的身份范围 | 归一为最小身份词：本科生 / 硕士研究生 / 博士研究生 / 专科生 / 教师 / 学生；"全校师生"记为师生 |
| `conditions` | 除身份外、需要逐条判断的资格约束 | **原子化**：一条只表达一个可判定约束（如"专业前30%""3—5人"），不写整句 |
| `materials` | 需要提交/上传的材料清单 | 按条目拆分，剥除数量词（"各一份"）与括号说明；文件名保留专有部分 |

> 上表是**评测标注口径**的 5 类字段（用于精确率 / 召回率计算），与系统实际输出的
> **14 类结构化字段**（总控文档 8.2）不是同一套集合：后者还包含年级 / 专业限制、报名起止、
> 活动举办时间、地点、联系人 / 电话 / 邮箱等，本轮由 `app/services/fields.py` 确定性抽取并逐字段附原文证据，
> 文体 3 类、`deadline_kind` 7 类。结构化字段契约与规则校验的用例见 `tests/test_smoke.py` 第 [13] 组。

### 3.2 三条容易分歧的规则

1. **"面向全校本科生、研究生"中的"研究生"** 记为 `硕士研究生`——通知不另作区分时，按硕士口径处理。
2. **"须签署《健康承诺书》"** 不计入 `conditions`——它是提交动作，归入材料与流程。
3. **优先项**（"有支教经验者优先""师范类专业优先"）计入 `conditions`，"鼓励参加""欢迎报名"不计入。

## 4. 数据处理流程

### 4.1 采集链路（真实数据入口）

```
config/sources.json（栏目配置）
   │
   ├─ 列表页发现    fetch_page → parse_list
   │                配置选择器优先；失效时按"链接数 + 日期数 - 导航词"给容器打分自动探测
   │
   ├─ 翻页          parse_pagination
   │                只认页面上真实存在的「下一页/查看更多」；跨目录的"查看更多"不算翻页；
   │                下一页 == 当前页视为到底（防自环）
   │
   ├─ 详情抽取      parse_detail
   │                正文容器按选择器优先级命中，再用"包含关系 + 体量比"剔除外层包装；
   │                块级换行、行内拼接；数字碎片回粘（"2025"+"年11月20日"）
   │
   ├─ 附件抽取      .article_appendix / 正文内 / 全页 a[href] 三处扫描
   │
   └─ 去重入库      content_hash（标题+正文 SHA-256）+ source_url 双闸
```

### 4.2 解析链路（结构化）

```
原始文本
   │
   ├─ 清洗（cleaner.py）      去导航、版权、推荐阅读等噪声行；合并被硬换行切断的短行
   │                          保留章节标题行（"四、材料要求"），它是后文抽取的上下文锚点
   │
   ├─ 切块（textutil.blocks）  按"章节标题 + 正文"切块；纯数字编号仅在短且无标点时才当标题，
   │                          否则「1.思想品德优良，身心健康；」会把整节正文切走
   │
   ├─ 去重（content_hash）     标题 + 正文归一化后取 SHA-256，重复录入返回 409
   │
   ├─ 分类（classifier.py）    领域词典加权打分 + 体裁强信号纠偏 + 行政事务降权
   │
   └─ 抽取（extractor.py）     日期上下文打分 / 对象归一 / 条件原子化 / 材料条目化
```

清洗不会改写原文标点：只统一全角数字，中文句读保持原样。原因是对外展示的"原文依据"必须与学校原文逐字一致，
否则用户核对时会认为系统篡改了通知。

## 5. 真实数据暴露的问题与修复

真实网页与手写样本的差距，是这一轮迭代最有价值的部分。以下五条问题都是接入真实栏目后才暴露的：

| 现象 | 根因 | 修复 |
| --- | --- | --- |
| 正文出现「报名截止时间 2025年月日20:00」 | CMS 把数字包进独立 `<span>`，`get_text("\n")` 让数字单独成行，清洗时被当作噪声行删掉 | 改为块级换行、行内拼接；并加"数字碎片回粘"兜底 |
| 截止日期抽取率仅 17%（42 条真实通知） | 同上，日期残缺后无法匹配 | 数字回粘后恢复；后续改用分文体口径（见下） |
| 「二、选拔条件」整节条件丢失 | `blocks()` 把「1.思想品德优良，身心健康；」当成章节标题，正文被切走 | 纯数字编号需同时满足"≤15 字且不含句读"才算标题 |
| 「硕博连读选拔」被判为校园活动、「招生简章」被判为奖助学金 | 词典里"选拔""资助"命中，但体裁其实是行政事务 | 新增行政事务词表（招生/学位/培养/学籍…）按比例降权 |
| 新闻稿抽出「报名截止」「报名材料」 | 对纯报道跑报名类字段抽取；且「X至Y」范围末端无条件加分，把赛事会期、公示期也推成截止日 | 新增文体闸门（`app/services/genre.py`），新闻资讯不抽报名类字段；范围加分要求办理语境；截止日标注 7 类语义类型 |

### 5.1 指标口径的修正

早期用「截止日期抽取率 55%」描述真实集，这个数字是错的：42 份里 18 份是新闻稿，
本身不存在报名截止，把"正确地留空"记成"没抽到"既低估系统，也掩盖了"在新闻稿上硬造字段"这一更严重的问题。
现在改为两把尺子，**由 `scripts/real_audit.py` 现场复算并生成 `docs/real_audit.md`**：

| 口径 | 结果 |
| --- | --- |
| 事务通知 21 / 公示公告 3 / 新闻资讯 18 | 按文体分层，不再混算 |
| 事务与公示类办理截止覆盖 | 20/24 = 83.3%，4 份留空均已逐条核对 |
| 新闻资讯报名类字段误报 | 0/18（绕过闸门对照会产出 25 个假字段） |
| 截止语义类型 | 报名 / 申报 / 提交 / 报送 / 征集 / 异议 / 办理截止，公示期结束不再笼统叫"报名截止" |

这一轮还顺带把开发集截止日期准确率从 91.7% 推到 **100%**（根因同为范围加分泛滥），
留出集保持 100%。

## 6. 数据质量说明与已知局限

| 问题 | 说明 | 处理 |
| --- | --- | --- |
| 标注存在主观边界 | "全日制本科三年级、四年级学生"属于对象还是条件，两人标注曾不一致 | 统一为：含年级限定仍记入 `target` 之外的 `conditions` |
| 开发集偏小 | 24 条足以支撑规则迭代，但不足以做统计显著性检验 | 明确标注为"开发集"，另设留出集防止过拟合自证 |
| 单校来源 | 真实采集集来自一所高校的 7 个栏目 | 规则按"体裁类型"而非"某校模板"组织；源配置与解析器解耦，换校只改 `config/sources.json` |
| 真实集未逐字段标注 | 42 份真实通知没有人工精确率标注，不能算 F1 | 改按文体统计「办理截止覆盖」与「新闻不误报率」两个可复算口径，`scripts/real_audit.py` 自动生成报告；不与测试集精确率混算 |
| 未覆盖 PDF / 图片通知 | 当前只记录附件链接，不解析附件内容；图片型通知记为 `content_type=image` | 列入后续迭代，需接入 OCR 与版面分析 |

## 7. 复现

```bash
python scripts/crawl.py --list                                   # 查看采集源
python scripts/crawl.py --all --limit 6 --save data/real_notices.json   # 重新抓取并落快照
python scripts/import_samples.py                                 # 导入构造样本 + 真实采集快照
python scripts/evaluate.py                                       # 开发集评测
python scripts/evaluate.py --set holdout                         # 留出集评测
```

导入构造样本时会把 24 条通知按时间均匀分布到最近 7 天，使看板的"采集趋势"曲线可用于演示；
真实采集样本的 `created_at` 取真实发布时间，不参与任何评测。
