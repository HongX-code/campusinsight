# 华为云服务选型与项目对接（RDS for MySQL + DCS for Redis）

> 状态：**方案与代码已就绪，真实开通与连通待资源验证**。
> 本文不声称已连通任何云资源；所有"已就绪"均指仓库内的 Terraform、脚本与代码路径可执行。
> 价格与规格以华为云控制台当日展示为准，本文只给量级，不作为报价。

## 1. 推荐配置（默认 Region：华北-北京四 cn-north-4）

| 资源 | 推荐配置 | 用途 | 关键取舍 |
| --- | --- | --- | --- |
| VPC | `192.168.0.0/16`，子网 `192.168.1.0/24` | 应用与数据服务同 VPC 私网互通 | 单子网够用；主备 AZ 由 RDS/DCS 自身跨 AZ |
| 安全组 | `app-sg`：仅 22/80/443；`data-sg`：仅 VPC 内 3306/6379 | 最小暴露面 | 数据库/缓存永不绑公网 IP |
| RDS for MySQL | MySQL **8.0**，**2 vCPU / 4 GB 主备**，**40 GB CLOUDSSD**，端口 3306 | 通知、解析结果、用户、待办 | 主备跨 AZ；预算敏感可降为单机 |
| DCS for Redis | Redis **5.0**，**1 GB 主备**，端口 6379，密码认证 | 解析结果缓存、问答加速 | 缓存可丢，不承担持久化 |
| ECS | 2 vCPU / 4 GB，40 GB 系统盘，2 Mbps EIP | 运行单 FastAPI 进程 | 由 auto-deploy 技能创建 |
| 部署形态 | systemd 单进程 + Nginx 反代 80/443 | 公网访问与 HTTPS | 单机，不做集群 |

## 2. 业务负载画像与选型依据

| 负载特征 | 现状（以仓库数据为准） | 对选型的影响 |
| --- | --- | --- |
| 数据规模 | 42 份真实通知 + 24 份开发集 + 8 份留出集；单条正文通常 < 8 KB | 数据量远小于 1 GB；40 GB 主要留给 binlog、备份与增长 |
| 读写比例 | 读多写少：列表/详情/看板/问答全是读；写入集中在采集、解析结果 upsert、人工审核 | 2C4G 足够；瓶颈更可能在 LLM 调用而非数据库 |
| 写放大 | 一次解析会写 `notice_analysis` 一行；批量解析最多几十行 | 不需要高 IOPS 规格，CLOUDSSD 40 GB 足够 |
| 并发 | 比赛演示级，通常 < 20 并发；单进程 uvicorn | 连接池 5 + 溢出 10 已覆盖；无需读写分离 |
| 缓存 | 解析结果 JSON（约 2–4 KB/条）与问答结果；数百条量级 | 1 GB Redis 远大于工作集，主备即可 |
| 可用性 | 答辩演示不能中断；允许秒级抖动 | RDS/DCS 主备跨 AZ，自动故障切换 |
| 合规与安全 | 学生画像为演示虚构数据；仍需最小权限 | 私网、安全组、IAM 子账号、密码不落代码 |

**结论**：这是一个"小数据量、低并发、读多写少、对演示可用性敏感"的负载。
选型优先保证**可用性与免运维**，而不是追求高规格；2C4G 主备是性价比拐点，
再往上加规格不会带来可感知收益。

## 3. 网络与高可用设计

```text
公网 ── EIP ── ECS(2C4G) ── app-sg(22/80/443)
                     │
                     ├── 私网 3306 ── RDS MySQL 主备（AZ-a / AZ-b）
                     └── 私网 6379 ── DCS Redis 主备（AZ-a / AZ-b）
```

- **VPC**：应用与数据服务同 VPC，数据服务不分配公网 IP/EIP。
- **子网**：`192.168.1.0/24`，网关 `.1`，DNS 使用华为云内网 DNS。
- **安全组**：
  - `app-sg` 入方向只开 22（限定来源 CIDR）、80/443（可限定）；
  - `data-sg` 入方向只允许 `192.168.0.0/16` 访问 3306/6379；
  - 默认出方向放行，应用可访问 MaaS 与采集目标域名。
- **高可用**：
  - RDS 主备：主备位于不同 AZ，半同步复制，故障自动切换（秒级到分钟级，取决于故障类型）；
  - DCS 主备：主备跨 AZ，故障自动切换；切换期间会出现短暂连接失败，应用侧按"缓存未命中"降级；
  - ECS 单机：演示够用；若要求更高可用，需多 ECS + ELB，超出本项目"单进程"约束，未纳入默认方案。
- **备份**：RDS 自动备份 7 天（03:00–04:00）；DCS 自动备份 7 天。正式环境建议按需延长并做异地备份。

## 4. RDS for MySQL 选型说明

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 版本 | MySQL 8.0 | 项目使用 SQLAlchemy 2.x + PyMySQL，8.0 兼容；`utf8mb4` 默认支持；社区支持周期长 |
| 规格 | 2 vCPU / 4 GB | 低并发 + 小数据量；4 GB 可容纳 InnoDB buffer pool 与连接开销 |
| 类型 | 主备（跨 AZ） | 演示不可中断；主备自动切换比单机多一份保障 |
| 存储 | 40 GB CLOUDSSD | 数据 < 1 GB；余量留给 binlog、备份、索引与后续增长 |
| 端口 | 3306 | 默认端口；安全组仅 VPC 内放行 |
| 字符集 | `utf8mb4` / `utf8mb4_unicode_ci` | 通知正文含中文标点、全角字符；避免乱码与排序差异 |
| 参数 | `character_set_server=utf8mb4`、`collation_server=utf8mb4_unicode_ci` | 建库建表统一字符集 |
| 备份 | 自动备份 7 天 | 演示回滚；正式环境延长 |

**与业务匹配**：项目没有复杂 JOIN、没有大事务、没有高并发写入；真正耗时在 LLM 解析（秒级）
与采集网络请求，数据库通常不是瓶颈。把预算放在"主备可用性"比放在"更大规格"更划算。

## 5. DCS for Redis 选型说明

| 项 | 选择 | 理由 |
| --- | --- | --- |
| 版本 | Redis 5.0 | 项目只用 `GET/SET/EX/PING/DBSIZE`，5.0 完全够用；兼容性稳定 |
| 规格 | 1 GB 主备 | 工作集 < 50 MB；1 GB 留足余量与碎片 |
| 类型 | 主备（跨 AZ） | 缓存击穿时仍可服务；切换期间应用降级为"未命中" |
| 端口 | 6379 | 默认端口；仅 VPC 内放行 |
| 认证 | 密码认证 | 避免内网横向访问；密码走密钥管理，不落代码 |
| 淘汰策略 | `allkeys-lru`（建议） | 缓存只做加速，宁可淘汰也不阻断写入；正式环境可按数据重要性调整 |
| 持久化 | 自动备份 7 天 | 缓存可重建，备份仅用于快速恢复 |

**与业务匹配**：缓存键是"解析结果哈希"，值约 2–4 KB，TTL 24 小时；即使全量丢失，
也只是重新解析，不会丢业务数据。因此 **Redis 不是系统的数据库**，不需要集群版。

## 6. 项目对接配置

### 6.1 连接信息

| 变量 | 示例（占位） | 说明 |
| --- | --- | --- |
| `DATABASE_URL` | `mysql+pymysql://root:<PWD>@<RDS_IP>:3306/gaoxiao_zhixun?charset=utf8mb4` | 只走私网 IP；密码经 URL 编码 |
| `REDIS_URL` | `redis://:<PWD>@<DCS_IP>:6379/0` | 只走私网 IP |
| `LLM_PROVIDER` | `maas` / `none` | 无密钥时保持 `none`，规则引擎兜底 |
| `LLM_API_KEY` | `<MaaS 密钥>` | 只放环境变量/密钥管理，禁止入库 |

生成方式：`deploy/cloud/provision.sh` 会把两条连接串写入 `deploy/cloud/cloud.env`（权限 600，
已被 `.gitignore` 忽略），不会打印到终端。

### 6.2 密钥与凭证管理

- **AK/SK**：只通过 `HW_ACCESS_KEY` / `HW_SECRET_KEY` 环境变量注入 Terraform；不写入 `.tf`、`.tfvars`、Shell 脚本。
- **数据库/Redis 密码**：写入 `terraform.tfvars`（本地、忽略提交）→ Terraform 创建实例 → 输出到 `cloud.env`；
  上传 ECS 后放在 `/etc/gaoxiao-zhixun/env`（root:root，600）。
- **应用密钥**：systemd `EnvironmentFile` 注入；容器用 `environment` 注入；均不落镜像。
- **建议**：使用 IAM 子账号 + 项目级资源组，只授予 VPC/RDS/DCS/ECS/EIP 所需权限；
  如条件允许，密码托管到华为云 DEW（数据加密服务），启动时拉取。
- **泄露处置**：任何出现在聊天、截图、日志中的 AK/SK 都应视为已泄露，立即在 IAM 停用并轮换。

### 6.3 连接池与超时（已在代码中落地）

| 位置 | 参数 | 值 | 作用 |
| --- | --- | --- | --- |
| `app/database/connection.py` | `pool_pre_ping` | `True` | 取连接前探活，避免使用被服务端断开的连接 |
| 同上 | `pool_size` / `max_overflow` | `5` / `10` | 单进程低并发，够用且不压垮 RDS 连接数 |
| 同上 | `pool_recycle` | `1800s` | 小于云侧空闲断开时间，避免 `MySQL server has gone away` |
| 同上 | `connect_timeout` | `5s` | 网络异常时快速失败 |
| 同上 | `read_timeout` / `write_timeout` | `30s` | 防止慢查询把请求线程挂死 |
| `app/services/cache.py` | `socket_timeout` | `3s` | 缓存慢时不拖垮请求 |
| 同上 | `socket_connect_timeout` | `3s` | 连接失败快速降级 |
| 同上 | `max_connections` | `20` | 单进程连接上限 |
| 同上 | `retry_on_timeout` | `True` | 偶发超时自动重试一次 |
| `app/services/llm_client.py` | `LLM_TIMEOUT` | `45s` | 模型慢时降级规则引擎（默认值） |
| 同上 | 失败冷却 | 10/30/120s | 连续失败时不再逐条等超时 |

**降级行为**：
- Redis 连接失败：启动时降级为内存缓存；运行中断连时读缓存按"未命中"处理、写缓存失败仅记录日志，业务不中断。
- RDS 连接失败：`/api/health` 返回 `degraded`，接口返回 500 并记录日志；不会回落到 SQLite（避免"看似正常但写错库"）。

### 6.4 初始化顺序

1. Terraform 创建 VPC/子网/安全组/RDS/DCS；
2. ECS 创建并加入同一 VPC/子网、绑定 `app-sg`；
3. 在 ECS 上 `python scripts/cloud_bootstrap.py --create-db`（建 `gaoxiao_zhixun` 库，utf8mb4）；
4. `--with-samples` 建表并导入演示数据；
5. 启动服务，访问 `/api/health` 确认 `database.kind` 为 RDS。

## 8. 与本地自建数据库/缓存对比

| 维度 | 华为云 RDS/DCS | 本地自建 MySQL/Redis（同机或同实验室服务器） |
| --- | --- | --- |
| 成本 | 订阅/按需，含运维与备份；短期演示偏高 | 硬件一次性投入低，但电费、带宽、备份介质与人力隐性成本高 |
| 可用性 | 主备跨 AZ、自动故障切换、自动备份 | 需自行做主从、Keepalived/VIP、备份脚本；单机故障即停服 |
| 运维复杂度 | 控制台/API 开通，补丁、备份、监控由云托管 | 安装、调参、升级、磁盘扩容、慢查询排查全部自管 |
| 安全性 | VPC 私网、安全组、IAM、审计、可选加密 | 依赖自建防火墙与运维习惯；公网暴露风险更高 |
| 弹性 | 规格/存储可在线升配，分钟级 | 受物理机限制，扩容需停机/迁移 |
| 数据合规 | 云厂商合规资质与区域可选 | 需自行承担合规与等保工作 |
| 适用场景 | 比赛演示、快速上线、小团队、无专职 DBA | 内网离线环境、长期固定负载、对云成本敏感且有运维能力 |
| 局限 | 连接数/规格上限、跨 AZ 时延、持续计费 | 故障恢复慢、备份易被忽略、扩容困难 |

**本项目结论**：比赛演示与答辩优先选云托管 RDS/DCS——把有限人力放在 AI 解析与可信链路上，
而不是维护数据库主从；同时保留 SQLite/内存缓存作为**本地开发与离线兜底**，两者不是替代关系。

## 9. 适用场景、优点与局限

**适用**：
- 高校通知类"小数据量、读多写少、低并发"的 Web 应用；
- 需要公网演示、断网可降级、答辩现场不能长时间停服的场景；
- 团队没有专职 DBA/运维，希望用控制台完成开通与备份。

**优点**：
- 开通快：Terraform 一次 apply 完成网络 + 数据库 + 缓存；
- 免运维：补丁、备份、主备切换由云托管；
- 安全基线清晰：私网 + 安全组 + IAM，数据库不暴露公网；
- 与项目代码解耦：只通过 `DATABASE_URL` / `REDIS_URL` 切换，本地 SQLite 不受影响。

**局限**：
- 持续计费，比赛结束后必须销毁，否则产生闲置费用；
- RDS 连接数与规格有上限，单进程 5+10 连接池是刻意保守值；
- DCS 主备切换期间会出现秒级连接失败，应用只能降级不能"零感知"；
- 跨 AZ 写入时延高于本地单机（通常 1–3 ms 量级），对本项目无感但对强一致高频写场景不适用；
- 未做读写分离/分库分表；数据量增长到百万级通知时需要重新评估。

## 10. 开通与验收清单

**控制台路径（无 Terraform 时）**：
1. VPC → 创建 VPC 与子网；
2. 安全组 → 创建 `app-sg`、`data-sg` 并配置上述规则；
3. RDS → 购买 MySQL 8.0 主备 2C4G 40GB，绑定 VPC/子网/`data-sg`；
4. DCS → 购买 Redis 5.0 1GB 主备，绑定同一 VPC/子网/`data-sg`；
5. ECS → 购买 2C4G，绑定 `app-sg`，分配 EIP。

**Terraform 路径**：见 `deploy/README.md` 路径 A。

**验收（必须逐项拿到输出）**：

```bash
curl -s http://<ECS_IP>/api/health
curl -s http://<ECS_IP>/api/ai/status
curl -s "http://<ECS_IP>/api/notices?size=1"
```

| 检查项 | 期望 |
| --- | --- |
| `/api/health` | `status=ok`，`database.kind` 含 `MySQL / 华为云 RDS` |
